# 发现与决策：四季环境系统

## 需求
- 当前视觉完整保留为春季，包括现有白天和夜晚。
- 新增夏、秋、冬，每季分别设计白天与夜晚。
- 季节切换必须平滑过渡，不允许硬切。
- 优先实现玩家第一眼可见的背景、云、花瓣替代粒子和光照。
- 新增短周期自动演示：每约 60 秒按春夏秋冬推进，昼夜继续只由按钮控制。
- 顶部季节菜单保留为测试快捷入口，手动选择后自动计时重新开始。
- 夏季需要轻柔青绿色而非当前偏黄；秋季暖橙、冬季冷色方向保持。
- 用户截图确认左侧固定米白开场前景没有随秋季变化，形成明显左右割裂。
- 夏叶、秋枫和冬雪需要从平面贴片升级为 SAKURA 风格的立体纸艺模型。

## 研究发现
- 项目使用 Three.js、Vite、TypeScript、anime.js，没有 Phaser EventBus/Constants.js 结构，需沿用现有模块架构。
- `ThemeController` 只管理 day/night，并已有查询参数、持久化、减弱动态和不同方向的过渡时长。
- `NightEnvironment` 是雾、四组灯光、天空昼夜进度的单一写入者，适合扩展为季节与昼夜组合的应用层。
- `sky.ts` 的天空 dome 已使用 shader 做昼夜混合；云是相机跟随的透明平面组；星空和探索眼睛依赖昼夜进度。
- `PetalField` 是 28 个实例化花瓣，支持碰撞 burst、风扇 applyWind，并已被多种家电演出依赖。
- `PetalField.setColdProgress()` 当前专用于冰箱技能，把樱花过渡成名为 `refrigerator-low-poly-snowflakes` 的冰晶；不能直接复用为冬季环境。
- `OpeningScene` 另有 22 个独立 Mesh 花瓣和弹簧环绕运动，必须单独接入季节，否则开场与游戏不一致。
- `GlobalToolbar` 当前拥有昼夜、音量和语言入口；季节应新增独立入口，不能改造昼夜按钮。
- 当前 `Game.ts`、`sky.ts`、`post.ts`、`styles.css` 等存在大量用户未提交修改，所有补丁必须局部、可审计。

## 设计审计
| 区域 | 当前评分 | 本轮目标 | 说明 |
|------|----------|----------|------|
| 背景与氛围 | 4/5 | 5/5 | 春季成熟，但缺少季节维度 |
| 色彩系统 | 4/5 | 5/5 | 当前春季统一；需建立四季昼夜数据合同 |
| 动画与缓动 | 4/5 | 5/5 | 昼夜过渡已有基础；季节需支持可中断连续过渡 |
| 粒子效果 | 4/5 | 5/5 | 樱花反馈成熟；需泛化轮廓并隔离技能冰晶 |
| 场景过渡 | 3/5 | 5/5 | 尚无季节云形/粒子交接策略 |
| 主题辨识 | 4/5 | 5/5 | 春季明确；夏秋冬需在无文字时可辨识 |

## 技术决策
| 决策 | 理由 |
|------|------|
| 新增 `SeasonController` | 不污染现有昼夜状态机，并支持单独持久化和查询参数 |
| 新增 `SeasonProfiles` 数据表 | 将天空、云、雾、灯光、CSS 和粒子参数集中管理 |
| 最终环境先季节混合、再昼夜混合 | 保证春夜→夏夜不会中途闪回白天 |
| 粒子保留实例化和无每帧分配 | 保持移动端性能和现有 fan/burst 反馈 |
| 春季值引用现有 PAL/DAY/NIGHT 数据 | 避免重构造成春季色差 |

## 视觉/浏览器发现
- 当前春日第一眼为奶油纸白、淡粉花瓣、柔云和冷暖平衡光照。
- 当前春夜使用中等月夜亮度，星空、云层和花瓣仍可读，电线与家电未被纯黑遮罩压暗。
- 开场画面的 22 片花瓣围绕插线束运动，是首屏主题辨识的重要组成，必须随季节变化。
- 环境粒子位于电线附近并参与风扇效果，季节粒子不可只做远景 CSS 装饰。
- Playwright 已由项目的 `vite` webServer 自动启动，目标视口可直接覆盖 1440×900 与 390×844。
- 现有诊断已暴露季节权重，但未暴露季节粒子显隐；为验证冬季环境雪与冰箱技能冰晶隔离，需要补充只读粒子诊断，不改变运行逻辑。
- 10 张实机截图已覆盖四季×昼夜桌面，以及夏夜/冬日手机端；四季在隐藏季节文字时仍可由云层、色温和粒子轮廓识别。
- 春日与春夜继续使用原粉色花瓣和原环境数值；夏夜绿叶降低，原萤火方案已在阶段 14 按后续反馈移除；秋夜保留暖叶；冬夜保留纸片雪。
- 手机端四个顶层全局按钮保持 44px，季节菜单在视口内，没有横向滚动。
- 2026-08-25 用户截图中，右侧秋日天空为暖橙，而左侧开场遮罩仍为春季米白；分界大约位于视口 38% 至 50%，属于 CSS 前景层未接季节变量，并非天空 shader 插值失败。
- 当前夏叶、秋叶与冬雪分别由单层 `ShapeGeometry`/`CircleGeometry` 构成，轮廓可辨识但体积、折痕、叶脉和受光不足，因此远看像贴片。

## 二次实施结果
- 自动轮换以活动帧时间累计，默认 60 秒，顺序固定为春→夏→秋→冬→春；单帧最多计入 1 秒，避免 WebGL 编译或后台恢复后跨过多个季节。
- 手动选择会同步写入保存值并把自动计时归零；自动换季不覆盖用户保存值，也不调用昼夜控制器。
- 夏季地平线由 `#FFEFD0` 调整为浅青绿 `#E4F1D8`，页面与左侧 wash 分别为 `#B8DFD2`、`#E5F3DF`。
- 开场 wash 使用 `--start-wash-rgb` 与 `--season-page-rgb`，颜色由连续插值后的季节环境逐帧写入；春季仍为原 `251,245,234`。
- Three.js 内部颜色为线性空间，CSS RGB 输出前必须 `convertLinearToSRGB()`；否则浅薄荷色会错误变为暗绿 `200,229,188`。
- 夏叶和秋枫改为薄挤出主体+叶柄+中央折脊，带弯折和正反面/侧边顶点色；冬雪改为六臂多瓣薄挤出纸晶，视觉上与冰箱尖锐低多边形冰晶区分。
- 三种非发光季节粒子改用 `MeshToonMaterial`；夏夜萤火虫最初使用 Additive `MeshBasicMaterial`，阶段 14 已固定关闭。

## 阶段 12 返工发现
- 用户确认上一版“立体纸艺”方向不适配：问题是厚度、硬角和大尺寸让季节粒子从环境装饰变成了视觉主体，破坏插线束层级。
- 正确基准应直接对齐 `PetalVisual.ts`：二维 `ShapeGeometry`、贝塞尔圆润轮廓、`MeshBasicMaterial`、双面透明、无深度写入。
- 原樱花轮廓约宽 `0.29`、高 `0.28`；夏叶、枫叶和雪花的包围盒应控制在相近范围，实例缩放只做轻微差异，不能再使用大于樱花一截的造型。
- 当前夏秋冬云的 `cloudOpacity` 分别为 `0.64/0.40/0.58`，明显高于“隐约可见”的目标；春季 `0.48/0.25` 必须冻结，其他季节应降低并让云色靠近各自 `skyMid/skyHaze`。
- `start-screen-wash` 是位于 Canvas 之上的 DOM 层，无法让 Canvas 内单独模型真正穿透到上层；可行的窄改方案是把不透明范围限制在左侧文案安全区，并在插头、插孔和线束进入的中右区域提前淡出为透明。
- 历史 `E:\AI\codexAI\sakula\arrow-cube` 已迁移为空目录，Git 将旧文件记录为删除；旧 Arrow Cube 设计需从 Sakura 仓库历史提交读取，Sakura Crossing 本体仍可从旧仓库根 `src/` 查看。
- Bing 对泛化的“Japanese pastel palette”检索结果污染严重，不能作为配色依据；后续改用可直接读取色值的专业配色站、传统日色数据或原项目调色板。
- 旧 Arrow Cube 与 Sakura Crossing 的共同设计方法不是“每季换一套饱和主色”，而是窄色域：蓝紫轮廓保持稳定，背景只用低饱和三段天空色，暖色集中在低空和小面积点缀。
- Sakura Crossing `src/core/palette.js` 明确写着调色板刻意保持狭窄；其天空核心仍是 `#8FBDEA / #D4E8FA / #FBE7E9`，说明新季节也应围绕粉蓝、奶白、灰紫做邻近偏移，而不是大面积纯绿或纯橙。
- Sakura Crossing 的天空注释把云定义为 “flat cel clouds / painted background flats”；因此夏秋冬云应该继续是二维软形状，但颜色接近天空且低对比，不需要真实白云的高亮度。
- Sakura Crossing 的花瓣纹理注释强调 “single rounded petal”；旧 Arrow Cube 也一直使用 `ShapeGeometry + MeshBasicMaterial`。这进一步支持三季粒子回归圆润面片，而不是模型化。
- GitHub 可检索到 MIT 许可的 `xiaohk/nippon-colors` 与 `syaning/nippon-colors`，可作为传统日色命名与色值参考；只读取色值数据，不引入其运行时代码。
- Nippon Colors 数据中适合本项目的低饱和参考包括：夏季 `白緑 #A8D8B9`、`瓶覗 #A5DEE4`、`水 #81C7D4`；秋季 `灰桜 #D7C4BB`、`鳥の子 #DAC9A6`、`蒸栗 #D9CD90`、`ときがら茶 #DB8E71`；共同高亮底色 `白練 #FCFAF2`。
- 这些传统色不应直接大面积铺满屏幕，而应与 SAKURA 原 `#8FBDEA/#D4E8FA/#FBE7E9` 混合：夏季只轻推向瓶覗/白緑，秋季只轻推向灰桜/鳥の子，橙黄集中给枫叶。
- Coolors/Color Hunt 动态页面无法可靠直接提取用户可见调色板，且页面包含品牌色噪声；本轮最终配色依据采用可验证的 Nippon Colors JSON + 旧 SAKULA 源码色板。

## 阶段 12 最终结果
- 夏叶、秋枫和冬雪均已统一为 `ShapeGeometry + MeshBasicMaterial` 的 Z=0 二维面片；最大轮廓控制在樱花的 0.82–1.12 倍，并通过实例长宽缩放提供轻微个体差异。
- 夏季最终使用薄荷灰绿地平线，秋季使用低饱和杏灰地平线，冬季使用雾蓝冷灰地平线；春季全部原值保持不变。
- 夏秋冬白天云主体透明度收至 0.14–0.15、云影收至 0.05–0.06，并把云色贴近各季天空中间色；截图中只保留若隐若现的移动轮廓。
- 开场 DOM wash 在约 52% 视口位置前完成淡出，右侧插头、插孔和线束直接显示 Canvas 原色，不再经过季节色层。
- `artifacts/season-system-flat-final` 的三季 1440×900 开场截图完成逐张目检；完整季节与工具栏回归 13/13、生产构建和 diff 检查均通过。

## 阶段 13 造型精修发现
- 用户提供的枫叶参考不是等距放射轮廓：中央裂片最高，左右主裂片向外伸展，底部两片更短，叶柄只占整体很短一段并略微弯曲。
- 第一轮五裂候选仍保留了过多次级尖角，缩小到开场粒子尺寸后会重新读成红色星形；第二轮删除次级尖角，只保留五个有明确主次的裂片。
- 枫叶整体最大边仍与樱花一致，颜色由旧橙黄改为 `#BC4F55 → #E47659` 的低饱和枫红到橙红渐变。
- 雪花不能只用重复半径形成放射星形；最终轮廓按六根主枝构建，每根主枝包含两对外伸侧枝，经过轻度圆角后仍保持枝晶识别度。
- `artifacts/season-shape-refine` 保存秋季第二轮与冬季完整/放大截图；实机目检确认雪晶侧枝和枫叶非等距裂片在游戏尺寸下可读。

## 阶段 14 夏夜与枫叶候选发现
- 截图中的夜间纵向色带来自季节浅色 wash 与固定紫黑 `::after` 遮罩的叠加边界；仅延长遮罩透明终点仍能看到色带，最终改为各季夜空邻近色的单层 wash，并彻底取消额外夜间遮罩。
- 夏季黄色光点来自 `summer-night-fireflies` 与 `opening-summer-night-firefly` 两层独立几何；两层均固定为透明且不可见，夏夜只保留绿色细叶。
- 低多边形枫叶参考的稳定识别特征是中央裂片最高、左右主裂片较宽、底裂片较短、内凹点深入叶心、短弯柄；等距放射会读成星形，内凹太浅则读成普通掌形叶。
- 已生成 6 款等比例候选预览；当前主观推荐 2 号，其深内凹在樱花级尺寸下仍清楚，外叶瓣也比锐角方案圆润。游戏内几何等待用户选定编号后再替换。
- 用户进一步明确目标不是缩小的完整枫叶插画，而是像现有樱花瓣一样的小型单面片：无叶脉、无内部多边形、无二级锯齿，只用少量圆润贝塞尔轮廓表达五裂特征。第二轮候选据此重做；当前推荐 6 号作为最简面片，1 号作为识别度更强的备选。
- 用户选定 6 号。第一版用自动圆角控制点连接后，实机缩小仍略呈星形；最终改为五组连续水滴状贝塞尔叶瓣，保留短弯柄和红橙纵向渐变。`artifacts/season-maple-v6/autumn-day-opening-v2.png` 显示正面圆润、侧翻轻薄，尺寸与樱花一致。

## 阶段 15 白天 wash 融合发现
- 春季左侧 wash 是当前视觉基准，不能通过改 CSS 全局透明度或渐变位置来“统一修正”，否则会破坏春季樱花主题。
- 夏季原 `#f3f4ea`、秋季原 `#f7eee5`、冬季原 `#f2f5f4` 均比各自白天天空/页面背景更亮，叠加在左侧文案区后会形成明显的浅色色块；将三者分别收敛为 `#e2ece5`、`#eee3d8`、`#e6eef1`，保留文字可读性同时减少边界反差。
- 复核截图像素后发现仅调亮/调暗 `startWash` 仍不够：夏季左侧约 `(225,235,227)`、右侧 Canvas 约 `(218,224,199)`，差异主要来自白天第二层 `season-page` 叠加和 wash 色相未对准实际天空。中间版本先改为 `#d9e0c8`、`#edd8b9`、`#dbe1d5`，并把第二层 page wash 的透明度按春季权重/昼夜进度插值为三季白天 0、夜间恢复 0.14；最终色值见阶段 16。

## 阶段 16 白天 wash 颜色校准
